SCRIPTS
=======

A script is a file with one KernelESP command per line.

Run a script:

  sh /home/file.sh

Example content:

  relay on light
  sleep 500
  relay off light

C-like automation is supported inside scripts:

  // Variables and constants persist across reboot.
  let irrigation.enabled = 1
  define HOT 40

  function heat_alert { relay on fan; mail health "Heat alert"; logger heat_alert }

  if (temp >= HOT && wifi == connected) { relay on fan; mail health "Heat alert"; logger heat_alert } else { logger heat_ok }

In scripts, keep if blocks and function definitions on one line. Use direct
commands inside if branches; call functions from cron, inputs or the shell as
whole actions.

Use timer commands instead of long sleeps for real actuators:

  if (irrigation.enabled == 1 && time < 10:00) { relay on valve1; timer once 600000 relay off valve1; logger zone1_started }

Create from the web UI:

  1. Open Scripts.
  2. Enter a path such as /home/test.sh.
  3. Write commands.
  4. Validate.
  5. Save.
  6. Run.

Create from the console:

  write /home/pulse.sh relay pulse light 500
  append /home/pulse.sh logger pulse_light
  append /home/pulse.sh relay status
  cat /home/pulse.sh
  sh /home/pulse.sh

Validate before running:

  sh -n /home/pulse.sh

Boot script:

  boot set /etc/boot.sh
  boot show

Typical /etc/boot.sh:

  ntp kick
  sensor begin
  relay status

Avoid long blocking commands at boot. Serial should remain responsive even when
Wi-Fi is down.

Scenes:

  scene add night relay off light; relay on security
  scene run night

Run a script from cron:

  cron add daily 22:30 sh /home/night.sh

Tips:

  - one command per line
  - test manually before automation
  - use clear names such as /home/morning_water.sh
  - avoid writing logs every few seconds
